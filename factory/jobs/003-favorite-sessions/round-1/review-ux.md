Each row is 26 px (30 px collapsed), so about 12 favorites take 300+ px of the sidebar. Many more and the tab list is squeezed to nothing or pushed off the panel, and the favorites that don't fit are clipped with no way to scroll to them. This is the main case for someone with many terminals: the pinned list can take over the sidebar and hide the tabs. — Put the favorites rows in their own `ScrollArea::vertical()` with a cap (for example `max_height` of about 40% of the available height, `auto_shrink([false, true])`), so the tab list always keeps a usable share. Keep the insertion line for drag reorder correct inside the scroll area, and give the area a distinct `id_salt` for expanded and collapsed (as the tab list does).

## Notes
- Defaults and keys: no invented keybinds. `add_favorite` and `open_favorite_1..9` are unbound on every platform, are in the palette (the "Add directory to favorites" command and the "Open favorite: X" rows), and have commented examples in `config.example.toml` and README that use no Alt chords. `open_favorite_N` returns false when the Nth favorite doesn't exist, so a user-bound key falls through to the shell. Good.
- Key and focus handling: while the dialog is open it is added to `modal_open` (input.rs) and to the focus-lock condition in `update`, so no keys reach the shell. Enter and Esc are only consumed while it is open. Minor: Enter is also consumed when a ComboBox popup is open (it will save instead of picking). It would be nicer to skip the Enter handling while the profile popup is open.
- Errors: a broken or unreadable favorites file goes through `diag::warn` to the config banner and keeps the old list, and dialog errors show inline. These match the vtt style. One gap: after the user fixes `favorites.toml`, the old "favorites file is invalid" banner stays until dismissed, because `problems` is only cleared in `reload_config`. Consider dropping the previous favorites problem on a successful `reload_favorites`. Conversely, a config reload clears `problems` and does not re-report a still-broken favorites file.
- Dialog path field: `~/src/api` typed in the dialog isn't expanded, so it fails with "doesn't exist". The CLI is fine because the shell expands `~`. Consider expanding a leading `~` in the dialog.
- Missing-path dimming (`mix(text, sidebar, 0.55)`) may fall below the minimum contrast the app honors elsewhere. Check it against the contrast setting in both light and dark themes. The tooltip does say why it is dimmed.
- Help window: nine "Open favorite N" rows in the shortcuts list make it long. Collapsing them into a single "Open favorite 1–9" row would match the README table. It needs the rebind UI to handle that, so it is optional.
- Behavior matches the rest of the app: ↻ reuses `reset_tab` and its confirmation, a closed tab drops the link, the files panel menu and the tab menu both have the add entry, the tab hover card names its favorite, and drag reorder uses the same insertion-line style as tabs. "Open in split" on a favorite that is already open just focuses it, which is reasonable, but the README doesn't say so.
- README: Features, the keybinding table, the actions list, the palette line, a Favorites section with the CLI and all three file locations, and the example config copy are all updated, in the README's plain style. No new config key, so nothing new to hot-reload. The favorites file is hot-reloaded through the watcher.
- No in-app editing of user files: the dialog edits only vtt's own favorites file.
