## Blocking
1. src/ui/sidebar/mod.rs:179 (`favorites_section` call) and src/ui/sidebar/favorites.rs:35-59 — the favorites section is drawn outside the tab list's `ScrollArea`, with no height cap. Every favorite takes a fixed 26 pt (30 pt collapsed), so on a short window or with large UI zoom a long list pushes the tab list down until it is squeezed out, and the sidebar header and tabs become unreachable. The rule is that the sidebar must scale with UI zoom. — Put the rows in their own `ScrollArea::vertical().max_height(..)` (for example about a third of the sidebar height, or a fixed number of rows). Keep the insertion-line and drag-reorder logic working inside it, and keep the separator below. Otherwise the tab list needs a guaranteed minimum height.

## Notes
- src/ui/sidebar/favorites.rs:85-86 — a missing directory's text is `mix(text_color, sidebar, 0.55)`. That is roughly 3:1 on typical dark themes, and it ignores the user's minimum-contrast setting. The hover-card `dim` color does the same thing, so there is precedent. It would still be safer to pass the result through `theme::ensure_contrast(.., c.sidebar, ~3.0)`, so the name stays legible. The row is also dimmed and its dot stays unchanged, so "missing" is conveyed by color alone apart from the tooltip. A small ⚠ or a strikethrough-free hint would help, but it isn't required.

It works, but a different glyph (▶) for the no-session state would match the label. Like the tab close button, it appears only on hover and is not keyboard reachable. That matches the neighbors.
